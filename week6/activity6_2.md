# Activity 6.2: Benefits of Modular Programming & Standard Library Exploration

## 1. ข้อดีของ Modular Programming (การแบ่งโค้ดเป็นฟังก์ชันและโมดูล)

| สถานการณ์ | ช่วยได้อย่างไร |
|---|---|
| **โปรเจกต์ขนาดใหญ่** | แบ่งโค้ดเป็นไฟล์/ฟังก์ชันตามหน้าที่ (เช่น `database.py`, `ui.py`) ทำให้หาโค้ดง่าย ไม่ต้องอ่านไฟล์ยาวหลายพันบรรทัด |
| **ทำงานเป็นทีม** | แต่ละคนรับผิดชอบคนละโมดูล ตกลงกันแค่ชื่อฟังก์ชัน พารามิเตอร์ และค่าที่ return ก็ทำงานคู่ขนานกันได้ ลด conflict |
| **Debugging** | เมื่อเกิด bug สามารถไล่ทีละฟังก์ชันได้ ปัญหาถูกจำกัดอยู่ในขอบเขตเล็ก ๆ เช่น ถ้าหารผิดก็ดูแค่ `divide()` |
| **Testing** | ทดสอบแต่ละฟังก์ชันแยกกันได้ เช่น `assert is_prime(7) == True` โดยไม่ต้องรันทั้งโปรแกรม |
| **Reusability (DRY)** | เขียนครั้งเดียวใช้ได้หลายที่ เช่น `my_utils.is_prime()` ใช้ได้ทั้งใน `main_program.py` และโปรเจกต์อื่น |
| **Readability** | ชื่อฟังก์ชันอธิบายตัวเอง เช่น `classify_number(num)` อ่านแล้วเข้าใจทันทีโดยไม่ต้องดูรายละเอียด |

ตัวอย่างจากสัปดาห์นี้: ใน `activity6_1.py` โค้ด Week 2 ถูกแยกเป็น `is_positive_negative_zero()` และ `is_even_odd()`
ทำให้ส่วน `main()` สั้นลง และนำฟังก์ชันไปใช้ซ้ำได้

## 2. Standard Library Exploration

แหล่งอ้างอิง: <https://docs.python.org/3/library/>  (โค้ดตัวอย่างอยู่ใน `activity6_2.py`)

| โมดูล | ใช้ทำอะไร | ตัวอย่างการนำไปใช้ |
|---|---|---|
| `datetime` | จัดการวันที่และเวลา | คำนวณจำนวนวันก่อนถึงวันสอบ, คำนวณอายุจากวันเกิด |
| `os` | ทำงานกับระบบไฟล์และระบบปฏิบัติการ | แสดงรายชื่อไฟล์ในโฟลเดอร์, สร้าง/ลบโฟลเดอร์, อ่าน environment variable |
| `sys` | ข้อมูลและการควบคุม Python interpreter | ดูเวอร์ชัน Python, รับ command-line arguments ผ่าน `sys.argv`, จบโปรแกรมด้วย `sys.exit()` |
| `collections` | โครงสร้างข้อมูลเพิ่มเติม | `Counter` นับความถี่คำ/ตัวอักษร, `defaultdict`, `deque` สำหรับคิว |

ตัวอย่างสั้น ๆ:

```python
from collections import Counter
Counter("programming").most_common(2)   # [('r', 2), ('g', 2)]
```

## สรุป

การแบ่งโค้ดเป็นฟังก์ชันและโมดูลทำให้โค้ดเป็นระเบียบ ดูแล ทดสอบ และทำงานร่วมกันได้ง่ายขึ้น
และ Python Standard Library มีเครื่องมือพร้อมใช้จำนวนมาก ควรตรวจสอบก่อนเขียนเองทุกครั้ง (don't reinvent the wheel)
